# /v2 cutover: make the redesign the default, then retire the old UI

Status 2026-10-01: **complete.** Owner gave the go; C1–C5 (axg.3–axg.7) merged. `/` is v2, `/v1` answers 410,
the old UI is deleted. The text below is the plan as written.
Supersedes the cutover bullet in `redesign/IMPLEMENTATION-PLAN.md` wave 4. E3 (btv.15) built
the mechanism, and this plan finishes the job.

## Where we are (measured 2026-10-01, not taken from docs)

- `/v2` is complete: epic `claude-scheduler-btv` closed with 26/26 children merged.
  `qa:v2:parity` is clean, and every difference between the two UIs is declared.
- **`/` already serves v2.** The owner set `v2Default='1'` on 2026-09-24 by hand, with a
  direct settings write a session handed them, and confirmed `/v1` still served the old UI.
  Nothing in git or beads records this. It was found by reading the live daemon
  (`claude-scheduler ui` printed `v2`).
- The old UI is still served at `/v1` and is still in the tree.

## The airlock

Same rule as project activation: an agent may prepare, only the owner may throw it.

## Phase A: the switch. Done.

- **2026-09-24, owner:** flipped `v2Default` to `'1'`. `/` became v2.
- **2026-10-01, agent:** E3 left nothing that could write the flag, so that flip needed a raw
  database write. Added the proper control:
  - `PUT /api/ui-default` with body `{ "ui": "v1" | "v2" }`. Order: validate, then Touch ID,
    then write. A refusal writes nothing. `GET /api/settings` reports `uiDefault`.
  - `claude-scheduler ui` prints the current default. `claude-scheduler ui v1|v2` switches,
    with Touch ID.
  - Design gate: no on-screen control. The flip serves no ranked job in
    `docs/design/launchbox.md`, so the CLI is the control. `/v1` is the way back without
    touching the setting.

## Phase B: soak, 2026-09-24 to 2026-10-01

- Window: 7 days of normal use with v2 as the default. That is the assumed meaning of "one
  release" for a local-only app.
- Anything the owner had to open `/v1` for becomes a bead under the cutover epic and blocks
  retirement.
- **Exit:** the owner says the old UI can go. That is a `human` bead, and every phase C bead is
  blocked on it.

## Phase C: retire the old UI (agent, after the owner's go)

Blast radius from the inventory below, in order:

1. **Favicon first.** `public/v2/index.html` links `/favicon.svg`, which lives in the old
   `public/` root. Move it to `public/v2/assets/favicon.svg` and update the link.
2. **Routing.** `/` serves v2 unconditionally. `/v1` answers 410 Gone and points to `/`.
   Remove `v2Default`, the `ui-default` route, `uiDefault` in settings and the CLI `ui`
   command. `sendExistingUi` goes. `assertNoSymlinks(public)` stays.
3. **Delete the old UI.** That is `public/index.html`, `style.css`, `app.js`, `projects.js`,
   `transcript.js`, `sessions.js`, `util.js`, `usage.js`, `auth.js`, `tooltip.js`, `icons.js`,
   `md.js`, `fields.js` and `vendor/` (marked and DOMPurify, which only `md.js` uses). About
   6,400 lines. Check the v2 transcript page has its own markdown path before deleting
   `vendor/`.
4. **Tests.** Delete `transcript.test.js` and `md.test.js`, which cover only old modules. In
   `frontend-conventions.test.js`, drop the checks that only cover old-UI files and keep any
   rule v2 needs, since `frontend-v2-conventions.test.js` exists. Remove the old-UI walk from
   `qa-route-walk.test.js`, and the old/v2 comparisons and flag tests from `v2-cutover.test.js`.
5. **Tools.** Retire `qa:v2:parity` (`tools/qa/v2-parity.mjs`), since there is no second UI
   to compare. Drop the old-UI shots and the `public/style.css` check from
   `tools/screenshots/capture.mjs`.
6. **Docs.** README, CLAUDE.md, `public/v2/README.md`, and this plan's status line.

Paths stay `/v2/...`. Moving assets to bare `/` paths is churn with no user-visible gain, so it
is out of scope.

**Separate decision:** `GET /api/sessions/:id/image/:p/:i` (server.js) has no caller in
either UI, only `tests/api.test.js`. It is orphaned, not old-UI-only. Either wire transcript
images into v2 or delete the route.
